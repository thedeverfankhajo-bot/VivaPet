# VivaPet — پت‌های سفارشی برای PocketMine-MP API 5

افزونهٔ همراه (Companion Pet) برای سرورهای Minecraft Bedrock با PocketMine-MP API 5.

VivaPet پت را به شکل یک موجودیت سفارشی در سمت سرور ایجاد می‌کند؛ پت پشت سر صاحبش حرکت می‌کند، وقتی فاصله زیاد شود به او نزدیک می‌شود، و افکت‌های تعریف‌شده برای همان پت را به بازیکن می‌دهد. دسترسی هر پت با Permission جداگانه کنترل می‌شود تا بتوان آن را به رنک‌های مختلف وصل کرد.

> **نکتهٔ ضروری دربارهٔ ظاهر پت‌ها:** ظاهر اختصاصی پت‌ها با Resource Pack همراه افزونه ارائه شده است. بازیکنان باید پک را از سرور دریافت و قبول کنند. بدون پک، کلاینت ممکن است مدل سفارشی را درست نمایش ندهد. این پروژه به Behaviour Pack وابسته نیست؛ PocketMine-MP منطق و موجودیت را مدیریت می‌کند و Resource Pack ظاهر کلاینت را فراهم می‌کند.

## امکانات نسخهٔ فعلی

- چهار پت با مدل و تکسچر اختصاصی: fox (روباه)، dragon (اژدها)، owl (جغد) و rabbit (خرگوش).
- یک پت فعال برای هر بازیکن؛ احضار پت دوم، پت قبلی را حذف می‌کند.
- فرمان‌های /pet hide و /pet show و /pet toggle برای مخفی/نمایش موقت پت بدون پاک‌کردن انتخاب ذخیره‌شده.
- فرمان /pet active برای مشاهدهٔ وضعیت پت فعال یا پت انتخاب‌شده.
- حرکت نرم‌تر با تنظیم فاصلهٔ دنبال‌کردن و ارتفاع/فاصلهٔ نقطهٔ همراه.
- دنبال‌کردن بازیکن با تنظیم سرعت و فاصله؛ در فاصلهٔ زیاد پت به صاحبش تلپورت می‌شود.
- افکت‌های مثبت جداگانه و قابل تنظیم برای هر پت.
- دسترسی رنکی با Permission مستقل؛ پشتیبانی از Permission مشترک برای بازکردن همهٔ پت‌ها.
- ذخیرهٔ پت انتخاب‌شده بر اساس UUID بازیکن و امکان احضار دوباره هنگام ورود/Respawn.
- حذف پت هنگام خروج، مرگ، انتقال جهان، از دست رفتن Permission، حذف دستی و خاموش‌شدن افزونه.
- پت تزئینی است: آسیب نمی‌بیند، برخورد ندارد و در Chunk ذخیره نمی‌شود.
- نصب خودکار فایل .mcpack در پوشهٔ Resource Pack سرور و افزودن آن به resource_packs.yml.
- شناسهٔ پت‌ها و افکت‌ها از allowlist انتخاب می‌شوند؛ مقادیر مهم تنظیمات نیز محدود می‌شوند.

## سازگاری

- PocketMine-MP با API 5.
- سورس PHP از PHP 8.1 به بعد استفاده می‌کند.
- برای نمایش ظاهر سفارشی لازم است کلاینت Bedrock پک را دانلود و فعال کند.
- وابستگی اجباری به پلاگین رنک خاصی ندارد؛ پلاگین رنک باید Permissionهای VivaPet را به گروه‌ها اعطا کند.

## نصب

1. پوشهٔ افزونه را در plugins/ قرار بده یا سورس را با DevTools به PHAR تبدیل کن.
2. سرور را اجرا کن. در اولین بار، افزونه VivaPet.mcpack را در پوشهٔ resource_packs/ کپی می‌کند و نام آن را به resource_packs/resource_packs.yml اضافه می‌کند.
3. سرور را **کامل خاموش و دوباره روشن کن**. تغییر Resource Pack پس از بارگذاری اولیه با /reload فعال نمی‌شود.
4. تنظیمات دانلود Resource Pack سرور را طوری نگه دار که بازیکنان بتوانند پک را دریافت کنند. VivaPet مقدار force_resources را بدون اجازهٔ مدیر سرور تغییر نمی‌دهد.
5. Permissionهای پت‌ها را به رنک‌های موردنظرت بده و داخل بازی /pet list را اجرا کن.

### ساخت با DevTools

ساختار پروژه استاندارد PocketMine است: plugin.yml در ریشه و کلاس‌های PHP در src/. اگر افزونه را به PHAR تبدیل می‌کنی، مطمئن شو فایل resources/VivaPet.mcpack هم در فایل خروجی PHAR قرار می‌گیرد؛ افزونه آن را با saveResource() از منابع خودش کپی می‌کند.

## دستورها

| دستور | کاربرد |
|---|---|
| /pet | راهنمای دستورها |
| /pet list | نمایش پت‌ها و وضعیت دسترسی |
| /pet summon <pet> | احضار پت؛ نمونه: /pet summon fox |
| /pet hide | مخفی‌کردن موقت پت؛ انتخاب ذخیره‌شده باقی می‌ماند |
| /pet show | احضار دوبارهٔ پت انتخاب‌شده |
| /pet toggle | تغییر وضعیت بین مخفی و فعال |
| /pet active | نمایش پت فعال یا انتخاب‌شده |
| /pet remove | حذف پت و پاک‌کردن پت ذخیره‌شده |
| /pet info <pet> | دیدن توضیح و وضعیت دسترسی |
| /pet reload | بارگذاری مجدد config؛ فقط مدیر |

Alias: /pets.

نکته: /pet hide انتخاب ذخیره‌شده را پاک نمی‌کند. اگر auto-summon فعال باشد، پت در ورود یا Respawn بعدی دوباره ظاهر می‌شود؛ برای پاک‌کردن کامل انتخاب از /pet remove استفاده کن.

## اتصال به رنک‌ها

VivaPet خودش رنک نمی‌سازد و نام گروه‌های پلاگین‌های دیگر را حدس نمی‌زند. اتصال از طریق Permission استاندارد PocketMine انجام می‌شود؛ کافی است پلاگین رنک، Permissionهای زیر را به گروه موردنظر بدهد.

| Permission | دسترسی | پیش‌فرض |
|---|---|---|
| vivapet.command | اجرای دستورهای پت | همه |
| vivapet.admin | اجرای /pet reload | OP |
| vivapet.pet.all | بازکردن همهٔ پت‌ها | هیچ‌کس |
| vivapet.pet.fox | روباه | هیچ‌کس |
| vivapet.pet.dragon | اژدها | هیچ‌کس |
| vivapet.pet.owl | جغد | هیچ‌کس |
| vivapet.pet.rabbit | خرگوش | هیچ‌کس |

برای نمونه، به رنک VIP این Permission را بده:

~~~text
vivapet.pet.fox
~~~

و به رنک بالاتر این‌ها را اضافه کن:

~~~text
vivapet.pet.dragon
vivapet.pet.owl
vivapet.pet.rabbit
~~~

یا برای بازکردن همهٔ پت‌ها از vivapet.pet.all استفاده کن. Permission در زمان احضار و در زمان فعال‌بودن پت دوباره بررسی می‌شود؛ اگر بازیکن دسترسی پت را از دست بدهد، پت فعال او نیز حذف خواهد شد.

## تنظیمات

فایل تنظیمات در plugin_data/VivaPet/config.yml ساخته می‌شود. تنظیمات اولیه:

~~~yaml
settings:
  auto-summon: true
  follow-interval-ticks: 2
  follow-speed: 0.28
  follow-distance: 1.65
  follow-offset: 1.55
  follow-height-offset: 0.12
  teleport-distance: 14.0
  effect-refresh-ticks: 40
  effect-duration-ticks: 100
  resource-pack:
    auto-install: true

pets:
  fox:
    name: "§6Ember Fox"
    description: "A swift companion that grants Speed."
    permission: vivapet.pet.fox
    scale: 0.78
    effects:
      speed:
        amplifier: 0
        visible: false
~~~

راهنمای گزینه‌ها:

- auto-summon: پس از ورود یا Respawn پت ذخیره‌شده را احضار کند یا نه.
- follow-interval-ticks: فاصلهٔ اجرای منطق دنبال‌کردن بر حسب Tick؛ مقدار کمتر پاسخ‌گویی بیشتری می‌دهد.
- follow-speed: سرعت حرکت پت؛ مقدار در بازهٔ امن محدود می‌شود.
- follow-distance: وقتی پت به این فاصله رسید می‌ایستد.
- follow-offset: فاصلهٔ افقی نقطهٔ دنبال‌کردن پشت بازیکن؛ مقدار مجاز 0.75 تا 3.5 است.
- follow-height-offset: اختلاف ارتفاع نقطهٔ دنبال‌کردن با بازیکن؛ مقدار مجاز 1.0- تا 2.0 است.
- teleport-distance: اگر فاصله از این مقدار بیشتر شد پت به صاحبش نزدیک می‌شود.
- effect-refresh-ticks: بازهٔ تمدید افکت‌ها.
- effect-duration-ticks: مدت افکت بر حسب Tick؛ ۲۰ Tick تقریباً یک ثانیه است.
- scale: اندازهٔ پت؛ در کد به بازهٔ 0.35 تا 1.5 محدود شده است.
- amplifier: قدرت افکت از 0 تا 4؛ Level نمایشی در بازی یک واحد بالاتر است.
- مدت افکت به‌صورت خودکار طوری محدود می‌شود که از فاصلهٔ Refresh تنظیم‌شده کوتاه‌تر نباشد.
- visible: نمایش ذرات افکت.
- resource-pack.auto-install: کپی و ثبت خودکار پک در تنظیمات Resource Pack سرور.

افکت‌های مجاز در نسخهٔ فعلی: speed, strength, jump_boost, resistance, night_vision, regeneration, fire_resistance, haste, water_breathing, absorption.

اگر بازیکن از قبل همان افکت را با سطح بالاتر داشته باشد، VivaPet آن را ضعیف‌تر نمی‌کند. هنگام حذف پت هم افکتی که قبلاً اعمال شده فوراً پاک نمی‌شود تا افکت‌های Potion/Beacon یا منابع دیگر اشتباهی حذف نشوند؛ فقط تا پایان زمان خودش باقی می‌ماند.

## اضافه‌کردن پت جدید

برای گونهٔ جدید فقط افزودن یک بخش YAML کافی نیست؛ چون هر کلاس و شناسهٔ کلاینت باید با هم هماهنگ باشند:

1. یک کلاس جدید PHP از PetEntity مشتق کن و شناسهٔ یکتای getNetworkTypeId() را برگردان.
2. شناسه و کلاس را در allowlist داخلی PetManager::ENTITY_CLASSES اضافه کن.
3. تنظیمات پت و Permission آن را به config.yml اضافه کن.
4. تعریف Client Entity، مدل Geometry و تکسچر همان پت را در Resource Pack اضافه کن.
5. شناسه‌های PHP و Resource Pack را دقیقاً یکسان نگه دار.
6. برای ویرایش مدل‌ها ابتدا `python tools/build_resource_pack.py --extract` را اجرا کن؛ فایل‌های استخراج‌شده در `resources/pack/` قرار می‌گیرند. پس از ویرایش JSON/PNGها، `python tools/build_resource_pack.py --build` را اجرا کن تا `resources/VivaPet.mcpack` دوباره ساخته شود.
7. مقدار version در manifest.json را افزایش بده، فایل پک جدید را هم در بستهٔ افزونه قرار بده و پس از نصب، سرور را کامل Restart کن.
8. مدل را با کلاینت Bedrock واقعیِ نسخهٔ مورد استفادهٔ سرور آزمایش کن.

عمداً کلاس PHP از config یا ورودی بازیکن به‌صورت پویا بارگذاری نمی‌شود؛ هر شناسه باید صریحاً در allowlist ثبت شود.

## امنیت و عملکرد

- ورودی پت فقط با شناسه‌های مجاز بررسی می‌شود.
- مالکیت و ذخیره‌سازی بر اساس UUID است، نه نام قابل تغییر بازیکن.
- Permission هر پت هم هنگام احضار و هم در زمان اجرای manager بررسی می‌شود.
- نام افکت‌ها allowlist دارد و Level/Duration محدود شده‌اند.
- پت‌ها در Chunkها ذخیره نمی‌شوند و در چرخهٔ عمر بازیکن حذف می‌شوند.
- افزونه هیچ درخواست شبکهٔ خارجی، اجرای shell، eval یا اجرای کد دریافتی از بازیکن ندارد.
- حلقهٔ حرکت فقط برای پت‌های فعال اجرا می‌شود؛ برای سرورهای شلوغ مقدار Tick و سرعت را با احتیاط تنظیم کن.

## بررسی و محدودیت‌های تست

در این پیاده‌سازی، بررسی ایستای PHP، parse کردن YAML/JSON و سلامت ZIP بستهٔ Resource Pack انجام شده است. بااین‌حال در این محیط یک سرور PocketMine-MP و کلاینت Bedrock متصل برای تست End-to-End در دسترس نبود؛ بنابراین قبل از استفاده روی سرور اصلی، روی یک سرور آزمایشی با همان نسخهٔ PMMP و کلاینت‌های بازیکنان تست کن.

نمایش مدل سفارشی به دانلود موفق Resource Pack از سمت بازیکن وابسته است؛ این افزونه نمی‌تواند به‌تنهایی کلاینتی را که پک را قبول نکرده مجبور به نمایش مدل کند.
